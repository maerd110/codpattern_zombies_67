# 战役、账号收藏与多人进度（0.2.34b 第一版）

## 玩法规则

- 对局采用一条完整故事历史。开局读取选定存档，房主移交不改变历史。
- 房主和队员都能获得本人参与完成的章节记录。结算时在线且仍属于本局的成员获得结算收益；中途加入、掉线后重连不影响，离开房间或结算离线者不获得。
- 队员保留路线后，保存完整剧情历史和自己的剧情仓库，保留不兼容的旧路线；连续游玩更新对应存档。
- 重要选择全队投票，首次平票重投，仍平票由房主在并列选项中决定；开始后加入的人不参加该轮，超时未投为弃权。
- 旧关回玩从原始章节起点建立新分支，不带入未来剧情；切换不会删除其他存档，删除需要确认。
- 剧情仓库按玩家的具体存档分别持有。加入更靠后的路线时继承该检查点仍持有的剧情物品，不恢复已消耗的道具。
- 收藏属于账号收益；接收他人历史不会自动获得未亲自完成章节的奖励。删档、回档不撤销账号收藏。
- 战斗装备、点数、银行不跨关，每关使用该关统一初始装备，没有自选带入武器。
- 恢复章节入口和部署者安排的安全检查点，不保存战斗中任意一颗子弹、怪物目标或打开的对话窗口。
- 房主离开自动移交在线房间成员，优先低延迟，同延迟按 UUID 排序。

## 玩家入口

默认 **H** 打开个人主页，可在 MC 按键设置修改。

- 我的旅程：新战役、存档详情、重命名、继续、历史章节回玩、确认删除。
- 当前房间：保留路线、剧情仓库；房主继续下一关、重试保存、结束游玩。
- 我的收藏：账号展示卡片和亲自完成的章节。
- 服务器成员：查看公开收藏架，可关闭自己的公开展示。

重要投票在没有其他界面打开时显示，不抢走编辑器。通关后房间停留在结算处，等待继续下一关或结束，不沿用普通局自动清场倒计时。结算或保存失败等待期间，全员离线60秒后释放房间；全员明确离开则立即释放，已保存进度保留。

普通非战役房间仍使用原来的流程。本版仍限制同一已部署地图同时一个房间；不同地图的故事状态独立，未实现同地图多个世界副本。

## 部署流程

部署工具 → **战役与跨关剧情**。管理员手持部署工具，全部僵尸对局结束后保存。卡片点击进入详情，滚轮查看余下内容。

1. 定义重要状态、跨关人物、剧情物品、任务和账号收藏；内部编号与中文名称分开。
2. 创建战役，按顺序添加章节、选择地图、设置通关收藏奖励。
3. 章节人物绑定：本关 NPC 内部编号 → 战役人物编号。模型、位置仍在原 NPC 编辑器设置。
4. 创建属于某章的战役事件，编辑触发条件和执行结果。
5. NPC 画布添加“触发战役事件”动作，填写事件编号。重要玩家选择块开启“全队投票”。
6. 分支、等待、选项显示条件可用“战役重要状态”与“存档剧情仓库”。
7. 保存配置，先用两关小流程验证，再接入正式长篇剧情。

自动事件条件为最低波次、已完成的本关 NPC 规则，设置的条件同时满足才触发；两者都不设置时仅由画布动作触发。可额外要求某个战役状态等于指定值。每个事件每章执行一次，完成记录随检查点保存。

| 执行结果 | 参数与行为 |
| --- | --- |
| 重要状态/选择 | 状态编号、值，如 elder_fate=saved |
| 战役任务 | 任务编号、active/completed/failed；active 显示任务指引 |
| 人物状态 | 人物编号、alive/dead/hidden，应用到本章绑定 |
| 发放/消耗剧情物品 | 物品编号、数量，当前交互者或全队每人一份 |
| 账号收藏 | 收藏编号，作为本章待结算奖励 |
| 安全检查点 | 检查点内部编号 |
| 完成章节 | 检查点内部编号，结算后可前往下一章 |

剧情物品是独立仓库中的任务数据，不会进入普通物品栏。原有 GIVE_ITEM/TAKE_ITEM 仍操作原版背包，不会自动跨关。

全队发放表示每人各一份；全队消耗要求每名在线队员数量足够，任一人不足整次事件回滚。个人消耗只影响当前交互者。全队只发生一次的交付放在同一事件中，完成记录防止重复开门/重复推进。

全队投票后的个人操作以服务器选取的在线存活执行者为交互者。需要所有人都扣除物品时，必须使用全队操作。

检查点和完成章节只能在开局、波间休整、自然通关阶段执行。NPC 动作执行后在安全阶段提交，避免把正在运行到一半的动作当成完整恢复点。

## 文件与恢复

配置：`<世界目录>/serverconfig/codpattern_zombies/campaigns.json`

进度：`<世界目录>/data/codpattern_zombies/campaign-state.json`

多人存档、个人剧情仓库和账号收益在同一文件事务提交；临时文件强制落盘后原子替换，失败不替换旧文件或已提交内存数据。不支持原子替换的文件系统会拒绝写入。

重启从最近成功检查点继续，恢复重要状态、任务、人物生死、本关 NPC 位置姿态和已完成规则、开启的屏障、按原顺序重放的地图事件、指引与波次；战斗资源重新初始化。

配置与数据有独立版本，未知版本拒绝读取。配置修订号防止覆盖另一部署者刚保存的修改。删除已发布章节、人物或事件后，旧档迁移目前需管理员处理，不要直接删除旧档依赖的编号。建议备份整个世界。

账号收藏首版显示卡片，没有能搬进战斗的实体枪。纪念枪专用模型、称号、实体展厅、离线补发以后添加。

## 后续范围

战役会话已有独立 instance UUID，房主身份与故事分离。下一步才是地图模板相对坐标和实例世界池；当前实体和地图清理仍使用原有房间系统，不能宣称已支持同地图多队副本。

之后可增加更完整的任务日志、分支章节出口、存档主动复制、旧版本迁移、纪念枪展示模型、称号与管理员全服发放。
