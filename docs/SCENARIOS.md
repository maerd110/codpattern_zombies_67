0.2.23b：修复框选线框重复应用摄像机变换而漂移的问题。保存和开局会检查目标区域原有方块，若不支持替换则报告方块和位置。若目标在对局中变成不支持替换的方块，事件不会写入部分场景，也不会将整局判负；该事件本局停用，下局恢复检查。错误记录在游戏日志，并仅向开启 NPC 调试模式的管理员显示。

0.2.22b 修复正式游戏中的坐标读取问题：保存、源区域读取、框选范围和目标位置均使用稳定的 x/y/z 格式，兼容读取旧版坐标键。框选时只显示场景选择提示，避免与原部署工具的 A/B 选点提示重叠。上一版已经读取过的场景请更新后重新框选并点击“读取源区域为目标场景”，再保存配置。

0.2.22b 的僵尸部署工具提供“波次与地图剧情”。客户端和服务端都需更新。手持部署工具，Ctrl+右键进入，选定关卡并先保存关卡部署修改，再点击此按钮。

界面有四页，条目以有独立边框、分类颜色和摘要的卡片排列。单击选中，再点“编辑所选”，或直接双击卡片进入独立编辑页；单击不会展开长表单。怪物、台词及区域变化也有各自的卡片列表，通过“管理怪物／台词／区域变化”进入。编辑时只显示当前条目。Esc 或“返回上级”保留修改并逐级返回，滚轮浏览卡片或编辑字段。底部“保存配置”提交全部四页，“重新读取”取回服务器版本。未保存离开会提示，保存时会检查其他部署者是否修改过配置；对局进行时只允许读取。收起查看地图后可移动和瞄准，再次 Ctrl+右键部署工具会回到本工作副本。

1. **波次怪物**：首次读取已有 `waves/wave_*.json` 的配置。新增波次或打开波次卡片，设置编号、首领入场音效、生命／伤害／速度倍率、同时存活上限与最快／最慢刷怪间隔。通过“管理怪物”进入怪物卡片列表，每张卡片可编辑种类、数量、独立倍率和击杀／助攻积分。间隔单位是游戏刻，20 刻约 1 秒；留空的可选参数沿用关卡默认值，填写 0 的无效倍率或间隔会被拒绝。空怪物列表可作为空波次。保存使用与旧文件相同的怪物、数量和参数验证。
2. **出场人物**：先新增人物，再编辑显示名字、名字颜色、正文颜色、粗体及斜体。颜色支持原版英文名或 `#RRGGBB`，也提供预设列表。人物编号保持稳定，修改显示名字不会破坏引用；删除仍被台词使用的人物时，先改掉相应台词的人物引用再保存。
3. **波前对话**：为指定波次新增台词序列，通过“管理台词”进入台词卡片列表；每句选择已定义人物或无名旁白，填写正文与“本句停留（秒）”，并可新增、删除、上移及下移台词，预览只显示在编辑界面，不广播给玩家。先等待“开播前等待”，再按顺序发到本房间聊天栏；每句停留结束后显示下一句，最后一句也会完整等待。只有波前对话与原有波次间歇都结束，才进入刷怪阶段，等待期间不消耗战斗阶段计时。旧 `wave_text` 文件中的首句延迟与后续句间隔会在首次导入时保留，末句默认额外停留 1 秒。
4. **地图事件**：打开事件卡片，设置触发条件、天气和时间，通过“管理区域变化”进入区域卡片列表。新增区域默认使用“场景快照”，也可切换为原有的“方块填充”。两种方式都在对局结束后恢复目标区域。

场景快照的部署步骤：

1. 在关卡外或附近另找位置，先搭好“变化后的样子”；关卡内原本的场景作为变化前状态保留。也可以先在原地搭好并读取目标快照，再自行把地图恢复成开局状态。
2. 在事件的区域编辑页点击“到地图框选源场景”。保持手持部署工具，左键点一个角、右键点另一个角，屏幕会显示选择范围；Shift+右键完成并返回编辑页。这些点击用于选择角点，不拆除或使用方块。也可直接编辑两端坐标。
3. 点击“读取源区域为目标场景”。服务器读取已搭建区域的实际方块与状态，生成保存在工作副本中的场景快照。空气也会保存，所以事件能同时新增结构和移除目标范围内多余的旧方块。读取操作不改变关卡、不自动保存其他修改。
4. 点击“到地图选择放置位置”，点选关卡中要变化的区域的最小坐标角作为原点。X/Y/Z 均向正方向放置，区域大小自动跟随快照；保持原方向平移，不旋转或镜像。也可直接编辑“目标原点”的坐标。
5. 保存配置，按波次、NPC 完成状态或 NPC 动作触发事件。触发时使用保存的快照，不再读取源场景；之后改建或拆掉源场景不会改变已保存的结果。需要更新快照时重新框选、读取并保存。

每个源场景最多 4096 格；读取时部署者需在同一维度、附近 256 格内的已加载区域。源场景可以在关卡边界外，实际目标范围必须在本关卡内，不能覆盖已配置的屏障和交互设备。每个事件仍最多 16 个区域、合计 8192 格。快照保留各格建筑材料、楼梯／台阶形态、原木轴向、门的开关等方块状态；沿用静态建筑方块的范围，不读取生物、容器、红石装置、液体等。遇到暂不支持的方块会明确指出其类型和坐标，整次读取失败，保留已有快照。

切换为“方块填充”后，可以像旧版一样设置起终点，选择一个方块填充整个区域，或“清空区域为空气”。切换方式不会主动删除已读取的快照，切回场景方式可继续使用。

事件有两种调用方式：

- 开启“自动检查触发”：在对局中检查最低波次以及指定 NPC 规则是否已完成，两项需同时满足；波次 0 表示没有波次限制，NPC 规则选“不限”则不检查规则完成。例如“达到第 5 波且 guide.quest 已完成”之后移除墙壁并变成雷雨。
- 关闭“自动检查触发”：由 NPC 画布中的“触发地图事件”动作调用。先保存事件，再重新读取 NPC 配置，从动作下拉菜单选择事件编号；可把玩家回答的出口连到此动作，也可以插在任意剧情步骤之后。此调用由剧情中的判断与连线控制，不再使用事件的自动检查门槛。

每个事件每局最多执行一次，重复触发不会重复修改地图。再次开局会清空事件完成记录。事件对方块的要求沿用 NPC 方块动作：支持静态建筑方块、空气和门类，不支持流体、重力方块、红石设备、容器等有连锁变化或实体数据的方块；不能覆盖已部署的屏障、窗口或交互设备。多格门应分别为上下格设置正确状态，已有屏障仍可用 NPC 的打开屏障动作。

天气可选晴朗、下雨、雷雨；时间为 0–23999，也可一键设为白天／夜晚，设置后房间显示时间固定为该值直到对局结束。**天气与时间只改变本房间玩家的画面，不修改整个维度的天气、太阳时钟或游戏规则。** 因而不会改变其他关卡，也不会改变服务器依赖真实昼夜／天气的生物或作物逻辑。玩家离开房间或对局结束后恢复所在维度的显示。方块变化则实际发生在关卡地图中，在正常结束、管理员结束、开局回滚或服务器关闭时恢复；方块原状先记录到持久恢复日志，再应用变化，服务器重启时恢复未清理的记录。

四页内容一起保存在关卡规则目录 `scenario.json`：

`<世界>/serverconfig/codpattern/maps/zombies/m-<关卡名编码>/rules/scenario.json`

首次保存前仍使用原有 `waves` 与 `wave_text` 文件。首次进入界面会导入这些文件，保存后 `scenario.json` 中的 `waves` 是运行时使用的波次配置，同文件中的 `dialogues` 是已部署的波前对话；原文件保留，之后手改旧文件不会覆盖已保存的界面配置。保存后以界面的完整台词列表为准：删除波前对话条目或清空其台词会取消该波播放，不会重新播放已导入的旧文本。只在从未通过本界面保存的旧关卡中继续读取旧 `wave_text` 文件。NPC 配置仍保存在独立的 `npcs.json`，无需移动。
